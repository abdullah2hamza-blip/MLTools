# Artifact selection, permissions and lineage

`inventory-draft.json` in the parent directory is the current selection ledger. It is not a frozen benchmark manifest. Metadata inspection for eligibility/annotation is disclosed separately from executing a case or tuning against its outcome.

Two published ACT bundles are pinned by complete model revisions, original small configuration/statistics bytes and SHA-256. Their pinned publisher cards explicitly declare Apache-2.0; license text accompanies the snapshots. No model weights or dataset episodes were downloaded. `prepare_act_candidates.py` retrieves only the fixed small allowlist and bounds each response to 128 KiB. It can validate the saved snapshots offline. Its decoded statistics use a bounded stdlib F32/F64 reader, not arbitrary deserialization.

Both ACT training configurations leave the dataset revision null. Current dataset schemas therefore corroborate names but do not attest the training snapshot, units, calibration or action modes. Dataset licensing is tracked separately: boccia's pinned current card declares Apache-2.0; move-cube has no card at the inspected revision (a 404 retrieval observation is recorded). The model-card license is not silently applied to dataset episodes. Only factual schema metadata is present; no episodes are included.

The ACT move-cube bundle shares the already evaluated SmolVLA move-cube dataset lineage. Its numerical normalization was executed as development evidence through the shared LeRobot processor, using the real published Safetensors file. It cannot become an independent held-out task. The ACT boccia bundle has been inspected for selection but has not been executed or used to tune outcomes. A final protocol must fix its role and all related lineage exclusions before evaluation; metadata inspection means it is not a blinded artifact.

`openpi-license.json` records primary API attribution for the explicit contributor response to [OpenPI issue263](https://github.com/Physical-Intelligence/openpi/issues/263#issuecomment-2638064959), including author association and date. It is broader evidence than the repository code license, but predates the selected GCS object generations and is not a generation-specific license notice. The original GCS statistics have not been vendored under an assumed code license. Final artifact eligibility and redistribution scope remain unresolved. The separate pinned OpenPI source code is used under its own Apache license with self-authored development statistics.

Candidate coverage is not completed benchmark coverage. Finalization still needs adequate independent lineages, grounded incident labels, permitted artifact eligibility, fair baselines and a committed split/protocol before final experiments. Family names, software embodiments and numerical processor tests must not be promoted into model-performance or hardware-calibration evidence.
