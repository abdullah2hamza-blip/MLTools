# Evidence and comparison scope

The implementation executes real pinned LeRobot components on controlled software fixtures. `validation/integration.json` records each case, expected status, actual status, intended-boundary validation and source/environment identities. The independent contract uses upstream SO-101 joint names and degree/normalized-gripper conventions, plus explicitly authored calibration semantics. Camera roles and physical targets are fixture specifications, not measured hardware facts.

The moving-anchor fault is injected by omitting `bind_action_queue`; the pinned upstream source already supports correct anchor preservation. This is a reproduction of the failure class discussed in [issue 3312](https://github.com/huggingface/lerobot/issues/3312), not evidence that every current policy path has that bug. Camera/joint/statistics/gripper/reset variants similarly mutate actual adapter wiring. No task-success benchmark or trained-model accuracy is measured.

## Published checkpoint metadata

`examples/published_so101/` additionally contains the small published configuration/statistics artifacts of [yutofujita/smolvla-so101-move-cube at 0220b37d](https://huggingface.co/yutofujita/smolvla-so101-move-cube/tree/0220b37dbcf1e0b2f6f5e21c64c75bf16fac6b69), with immutable URLs/digests in `source_manifest.json`. This is genuine checkpoint metadata, rather than the earlier calibration configuration. No model weights or dataset episodes were obtained.

The preparation script verifies pristine source bytes, extracts action statistics through the safe Safetensors loader, and records the derived files separately. It does not instantiate the saved registry, tokenizer or model. Real pinned LeRobot rename/normalize/unnormalize classes then run against those published parameters, while the core calculates independent scalar expectations. The 50-step numeric chunk is fully consumed. This is processor-path evidence, not end-to-end SmolVLA inference.

The saved metadata supports MEAN_STD numerical action normalization and front/wrist rename routes. It provides no authoritative physical units/action modes or joint-name correspondence, and its training dataset revision is null. Consequently positional dimensions are explicitly labeled `dimension_0` etc.; no physical joint mapping is invented. `camera3` appears in model features without a physical role, and model padding to 32 dimensions, observation-state normalization and image resize/padding are outside this test. Named controller commands are not constructed. Those limitations yield UNKNOWN even when all supported numeric checks pass. The deliberately wrong deployment-statistics variant yields FAIL at `action.unnormalize` despite the other unknowns.

Rebuild derived metadata offline from committed pristine sources with `uv run --extra lerobot python scripts/prepare_public_checkpoint.py`. Initial retrieval, only if source files are absent, requires explicit `--download`. The two source statistics tensors are byte-identical; derived training/deployment vectors are separately identified. Changing a derived manifest alone does not prove that an extraction is faithful: preserve and verify its source artifacts and review the extraction code.
